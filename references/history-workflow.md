# 历史带货表现：页面采集与拆解

本模块由技能通过当前浏览器读取页面，脚本负责确定性计算。没有独立爬虫，不需要FastMoss API，也不持久化登录凭证。

## 入口与条件

接受达人详情链接、ID或上一步搜索名单。沿用已明确的国家、币种和统计周期。未指定样本时可用已有名单的一位验证流程，说明是验证样本。未指定竞品时先输出商品/店铺推广历史，不自行指定竞品；竞品分析接受明确品牌对应的商品ID、店铺ID集合，商品标题关键词只能形成待确认映射。

## 页面执行步骤

1. 通过当前浏览器清单发现FastMoss标签页，复用登录状态。读取达人身份、国家、数据总览。确认统计周期，不把总览累计GMV当作28天GMV。
2. 点击“视频分析”锚点，读回页面状态，等待懒加载完成。记录视频列表周期、页码、排序及总页数。2026-11-09样本显示每页5条；按每次当前页面观察，不硬编码控件编号或页数。
3. 对每行保留视频ID、来源链接、发布时间、视频类型、销量、GMV、播放量、互动率、挂车商品链接及原文字段。中文万/亿和美元符号须按原文转数，保留原文。非带货视频不混入带货效果样本。
4. 按需翻页，用视频ID去重，直到约定页数/条数、末页或权限/额度边界。每次翻页核对页码和第一条ID变化，防止重复读取。默认无范围时先采一页做可审阅样本，披露非全量；用户明确要全量时继续到可访问范围末页，不以首屏代替全量。
5. 点击“直播分析”，独立核对周期。采集直播ID/链接、开播时间、销量、GMV、带货商品数、动销商品数、累计观看人次、UV价值、商品列表。零场次、暂无数据、未加载和不可访问分别记录；只有明确显示零场次才能说页面显示未直播，不推断历史从未直播。
6. 点击“带货商品列表”，记录该模块独立周期、商品ID、价格区间、达人带货销量/GMV、佣金、店铺ID。TOP5合作店铺记录保留为平台原文，其“合作商品数”不等于付费合作次数。商品上架时间不是达人合作时间。
7. 需要效果或评论分析时进入视频/直播详情，滚动到对应商品模块并等待加载；记录每个指标的统计区间。同一视频详情与列表有差异时分别保留，不拼接不同时间分母。仅显示评论数量时，舆情标记“未获得正文”。若页面提供正文，按可见范围保存评论稳定ID、内容、来源、日期，随后人工/AI逐条给情绪标签及依据；报告标签为推断，不宣称全量情绪。
8. 将证据保存为批次 `evidence.json`，运行下面分析命令，检查报告与原文一致后写operations。不要让写库或飞书配置阻塞历史分析。

```text
python scripts/history_analysis.py outputs/<批次>/evidence.json --output outputs/<批次>
```

## 证据输入契约

真实示例：`outputs/2026-11-09-history-aidana/evidence.json`。顶层必填creator_id、source_url、collected_at、currency、period、coverage。records每项必须有kind(video/live)、字符串id、source_url、period、currency。period/currency必须与批次一致，混合周期分批分析。数字未知填null或省略，不填0。

可选gmv、units、views、orders、clicks、refund_orders。保留对应的 `*_raw` 和范围说明。只有确认订单、点击、退款及GMV是同一归因周期/范围时才设置 `denominators_verified: true`；确认views与GMV范围一致才设置 `views_scope_verified: true`。绝不能为获得输出而默认设置这两个标志。

products为商品数组，每项id、shop_id、name；只有展开列表后已确认完整挂车集合时设置 `products_complete: true`。competitors数组每项name及product_ids/shop_ids。按(kind,id)去重统计已观察到推广的视频/场次；重复但字段冲突报错，需回原页面核验。只有完整挂车集合中仅1商品的记录可将场次GMV用于该商品效果，其余不分摊全场GMV。

comments每项id、text、source_url，可加sentiment(positive/neutral/negative)、sentiment_basis。无依据的标签归unclassified。保留采样规则，不能由评论数量推断负面率。

## 指标与投产潜力

- GMV/销量 = 件均销售额，不能称订单客单价；GMV/订单数才是订单口径客单价。
- 订单/点击才可作已核实口径点击转化率。销量/播放量不叫转化率。退款订单/订单为订单退款率，不与件数退货率混淆。
- 视频和直播分开输出样本GMV、中位数、样本最高单条贡献、有效记录数。头部排序第一页存在选择偏差，不用于预测平均合作效果。
- 预测以保守/基准/乐观成本情景表达，不由平台总GMV直接给ROI。顶层scenarios每项name、assumed_gmv、margin_rate、commission_rate、refund_loss_rate、fixed_cost；金额均为批次币种。fixed_cost包含坑位、样品、物流、投流等，退款损失率与毛利成本需避免重复计入。此模型仅适合已把变动损失折算为GMV比例的情况。
- 净贡献率=毛利率−佣金率−退款损失率；盈亏平衡GMV=固定成本/净贡献率，净贡献率≤0时无可行平衡点。利润ROI=(GMV×净贡献率−固定成本)/固定成本。零固定成本时ROI未知。
- 没有用户成本或完整同类目证据时，交付“能证明的表现、不能证明的条件、补数清单”，不生成精确报价或投产预测。
