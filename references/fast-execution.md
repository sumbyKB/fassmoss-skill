# 快速网页执行

仍使用当前已登录FastMoss网页。优先浏览器文档提供的Playwright DOM接口；不要用FastMoss API、隐藏状态、Cookie导出或自建HTTP采集代替页面。

## 已验证接入

在cua_repl中：`const browser = await cua.getBrowser({id: 当前发现的浏览器ID})`，读取首次返回的文档；接口支持时调用browser.nameSession。用browser.user.openTabs发现用户标签，再browser.user.claimTab绑定；browser.tabs.list只列当前已接管标签，空列表不代表用户没打开网页。不要硬编码历史tab ID。

首次用tab.playwright.domSnapshot()获取控件和表格结构，后续优先使用getByRole/getByText定位。读取已观察表格：`tab.playwright.getByRole('table').getByRole('row').allTextContents()`；有多个表时先按表头定位，不能把商品、达人、直播列混用。结构化整表采集函数在scripts/bulk-page.mjs，只读取已观察到的表格DOM，返回表头、原文单元格和完整链接；不靠字符串拼接猜ID。creatorRows按稳定ID去重，冲突报错。

## 减少调用

1. 初次发现控件后，在同一次工具调用中完成确定的连续输入；互相依赖的新菜单先读新状态。填写结束验证一次，不在每次输入后读取整页。
2. 整页表格一次提取，不对10行做10次读取；翻页后核对页码/首ID变化，再提取该页。部分页始终标明覆盖范围。
3. 已有当前观察证明的查询链接可直接复用，保留用户条件；未知参数走页面控件，不枚举猜测。
4. 深入候选时只加载用户问题所需模块，先以类目相关性排除不适配者，再取其余视频/直播明细。不能以提速为由省略明确要求的字段核验。
5. 只对已变化模块读取，避免每次getAXState+截图双读。平台提示、登录失效、加载失败与真实空结果分开判断，禁止盲目重复点击。
6. 采集结果完成后，飞书先读真实结构，一次批量写入，核验返回ID；不逐行交替写入与读取。未核实报价、30天周期、转化等明确标注，不能将候选标成全部符合。

## 时延预算与停止条件

2026-11-09实测：已登录搜索页面domSnapshot为21251ms；整张表11行（含表头）allTextContents为21091ms。此前AX整页通常约42秒，DOM读取约减半；不能宣称单次调用已到毫秒级，也未证明完整5人任务提速比例。

每批记录调用次数、提取条数、总耗时及失败阶段。发现单次连接仍约21秒时，减少调用数；不要加固定sleep。使用当前浏览器运行时内置等待和必要的元素就绪等待。出现失联，先重新发现标签并重新绑定一次；仍失败记录阻碍，不连续重复42秒整页读取。平台额度/权限限制不可借换通道绕过。

目标是减少无效往返，不设置无法保证的业务完成时限。对5位候选的完整跨页面取证仍需按实际页数计时。
