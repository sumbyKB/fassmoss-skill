# 2026-11-09 商品分类精确筛选 + 分类树抓取（重大突破）

## 背景

用户指出「跑步鞋分类其实有，要找到对应品类」，并建议「先获取所有分类类型，再找最符合的」。之前误判为"分类筛选做不了"，实则是没找到正确的分类 ID 参数。

## 关键突破

1. **分类筛选参数是 `l1_cid`**（一级分类 ID）：点击一级分类，saleRank 请求带 `l1_cid=<id>`。已实测：鞋靴=6、箱包=7、美妆个护=14、居家日用=10、食品饮料=24、汽车与摩托车=23。
2. **saleRank 响应体可读**（`waitForResponse` 精准捕获）：每条商品带 `all_category_name`（完整三级分类路径数组，如 `["美妆个护","洗浴与身体护理","保湿油、按摩油"]`）、`real_price`（售价）、`shop_info.name`（店铺=品牌）、`sale_amount`（销售额）等完整字段。
3. **分类面板结构**：左列=一级分类（x≈273）、右列=二级分类（x≈493），用 x 坐标区分。一级分类 30 个，二级随一级展开。
4. **"跑步鞋"实为"运动鞋"**：FastMoss 泰国站无"跑步鞋"独立分类，对应「鞋靴(6)」下的「女士/男士休闲运动鞋」或「运动与户外」下的「运动鞋」。

## 交付

### 新命令 `categories`（scripts/rpa/fastmoss-rpa.mjs）
抓「一级分类名 → l1_cid」映射，存 categories.json。用 x 坐标区分一级/二级，逐个点击捕获 l1_cid。

### `product` 命令增强：`--category-id`（l1_cid）
精确筛一级分类（如 `--category-id 6` 筛鞋靴），实测抓到纯鞋子数据（50 个商品全是鞋类）。

## 实测验证（泰国站，鞋靴）

- `product --category-id 6 --days 14 --pages 5` → 50 个商品，分类全是鞋类（女士凉鞋&人字拖×15、女士拖鞋×9、男士拖鞋×9、女士休闲运动鞋×3…）。
- `analyze-product --category 运动鞋 --brand POSE` → 品牌对比 + 价格带正常产出。

## 已知限制

1. `categories` 命令只可靠抓一级分类（点击一级分类触发 l1_cid 稳定）；二级/三级分类 UI 自动化不稳定（点击后面板 DOM 变化导致后续定位错乱），二级/三级靠商品「分类」字段（all_category_name 末级）在分析层过滤。
2. 一级分类点击会触发 `/api/captcha/verify`（平台反爬探测），但用 `l1_cid` URL 参数直接筛**不经过 UI 点击**，不触发验证码。
3. 分类树完整 ID（二级/三级）数据在前端，未找到独立接口；一级 l1_cid 已够精确筛到"鞋靴/箱包"等大类，二级靠字段过滤。
