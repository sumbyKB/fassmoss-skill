# 2026-11-09 商品销售分析能力（细分品类 / 品牌对比 / 价格带）

## 需求

业务原话：「我一般是要分析近两周的细分-跑步鞋的销售情况，按销售金额排，然后分析我们品牌和其他近几个月排名都相近的品牌的对比，还要区分价格带」。要求做成 skill 里通用能力，大白话就能驱动。

## 交付内容

### 1. 新命令 `product`（scripts/rpa/fastmoss-rpa.mjs）
抓 FastMoss 商品销售榜 `/zh/e-commerce/saleslist`，参数：
- `--country 泰国`（国家/币种自动）
- `--days 1/7/14/30` → 映射 date_type（1日榜/2周榜/3月榜）
- `--pages N`、`--sort gmv`（按销售额排序）
- `--category`（分类名，抓全量后分析层过滤）

关键实现：
- **date_value 不硬算「今天」**：首次无 date_value 加载，读回 `location.href` 真实值再翻页（实测取当天返回空，平台有效日期是昨天/上月）。
- 商品榜列解析：排名/商品/所属店铺(≈品牌)/商品分类/佣金/销量/销售额/总销量/总销售额 + 商品「售价」区间。
- 接口 MSG_SAFE_0001 签名，只能读 UI DOM（`PRODUCT_EXTRACT_FN` 注入浏览器提取）。

### 2. 新脚本 `analyze-product.mjs`
对 product 产出做：①细分品类按销售金额排序 ②品牌对比（本品牌 vs 前后 N 名竞品）③价格带分档（低价/中价/中高价/高价）。产出 `brand-comparison.md` + `.json`。

### 3. 文档
- `references/product-workflow.md`：大白话 → 参数映射表 + 关键事实 + 边界。
- SKILL.md / README.md 接入商品分析说明与命令示例。

## 实测结果（泰国站，月榜 2026-10）

- product 抓 20 页 200 个商品，20/20 成功。
- 保湿品类分析：6 商品，YerpallThailand 高价带第一（฿4275万）、Ness herbal 中价带第三，价格带分档 高价42.5%/中价38.7%/中高价18.9%。

## 已知限制（诚实披露）

1. **细分品类精确筛选未完全自动化**：FastMoss 商品分类是三级 Cascader 弹层，`category` URL 参数不生效（传中文名无效），且 UI 点击分类会触发**腾讯验证码遮罩**（`#tCaptchaMaskLayer`，平台反爬，本技能不绕过验证码）。当前方案是「抓综合榜全量 + 分析层按分类字段过滤」，综合榜 Top 200 以美妆护肤为主，跑步鞋等低频品类可能覆盖不到。**后续增强**：等风控解除后抓分类树接口拿分类 ID 精确筛，或人工先点一次分类再抓。
2. **近两周 ≠ 精确 14 天**：平台只有日/周/月榜，近两周映射月榜（date_type=3），date_value 为自然月（如 2026-10）。
3. 「所属店铺」≈品牌是推断（泰国品牌名常=店铺名），非平台品牌实体。
4. 价格带由商品售价区间中位数估算，非交易均价。
5. 无订单级客单价、退货率、真实品牌方身份。

## 变量化设计（2026-11-09 追加）

按用户要求「跑步鞋、店铺名等都是变量，方便后期复用」，把能力做成变量驱动：

- 六个变量：`--country` 国家 / `--category` 细分品类 / `--days` 时间 / `--brand` 本品牌 / `--nearby` 竞品范围 / `--top` 条数；价格带阈值在 `analyze-product.mjs` 的 `TIERS` 常量。
- `references/product-config.example.json`：变量配置模板，改字段即可复用，不用记命令。
- `SKILL.md` / `product-workflow.md` 写入「大白话 → 变量 → 命令」映射表，业务换一个词（跑鞋→箱包、品牌A→品牌B）即可复用。
- 注意：连续大量 UI 探测会触发腾讯验证码（2026-11-09 18:5x 实测触发），触发后连数据读取都返回空。需冷却后再操作。
