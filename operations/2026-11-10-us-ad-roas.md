# 2026-11-10 美区投流 ROI 数据源探查记录

## 目标
用户要「投流分析 ROI」= GMV ÷ 广告花费，近一个月的耳机类目数据。

## 关键结论：找到了正确数据源

FastMoss 投流 ROI 数据在 **广告创意中心**（导航「广告」→ 热门广告案例）：

**页面**：`/zh/creativecenter/search`
**数据接口**：`/api/da/V4/search`

### 接口参数
- `page` / `pagesize`（默认 12）
- `da_type=1`（广告类型：1=电商、2=游戏、3=应用）
- `region=US`（国家）
- `l1_cid=16`（一级分类，16=手机与数码）
- `_time` + `cnonce`（签名，MSG_SAFE_0001 校验，不能直接改参数 fetch）

### 接口返回的关键字段（投流 ROI 完整数据）
| 字段 | 含义 |
|---|---|
| `roas` | ROAS = 投流 ROI（GMV ÷ 花费） |
| `estimate_cost` | 广告消耗/花费（$，如 11.74） |
| `estimated_conversion` | 预估转化 |
| `play_count` | 播放量 |
| `advertiser` | 广告主/品牌 |
| `desc` | 广告文案 |
| `put_days` | 投放天数 |
| `first_put_date` / `last_put_date` | 投放起止日期 |
| `ad_count` | 关联广告数 |

**GMV = roas × estimate_cost**（ROAS 定义反推）。

## 未解决的关键问题（需用户配合）

1. **时间范围**：接口默认返回「近1天」投放的广告（put_days=1，都是当天）。「近一个月」需要通过页面的「投放时间」日历选择器 UI 切换，但：
   - 接口有 MSG_SAFE_0001 签名，不能直接改 query 参数（测试 put_days/days/date_type 等全部返回签名错误）
   - 时间筛选在页面是日历选择器（不是下拉），需要 UI 点选
2. **ROAS 值可疑**：近1天数据的 ROAS 全是 3.13/3.12 整齐划一的默认值，且大量广告 ROAS="-"、花费=$0（数据未回传）。真实近30天累计 ROAS 需切时间范围后才准。

## 补充：日期参数已找到 + ad 命令固化（2026-11-10 12:17）

### 时间参数（关键突破）
用户手动选日期后，接口请求带时间参数：
```
/api/da/V4/search?...&last_start_date=2026-10-09&last_end_date=2026-11-09
```
- **`last_start_date` / `last_end_date`** = 投放时间范围（YYYY-MM-DD）
- URL 直接带这两个参数即可生效（页面日期显示同步变化）

### 新增 `ad` 子命令
- 用法：`ad --country 美国 --category-id 16 --start 2026-10-09 --end 2026-11-09 --pages 10 --out xxx.json`
- 也支持 `--keyword`（按广告文案关键词筛）
- 抓取字段：roas / estimate_cost / advertiser / play_count / desc / put_days / first_put_date / last_put_date
- GMV = roas × estimate_cost

### 实测
- 近30天（10-09~11-09）：120 条广告、15 条耳机相关
- 短日期（11-01~11-09）：60 条广告，验证日期参数可灵活调整

### 数据口径（重要，已写入 SKILL.md）
- roas/estimate_cost 是平台估算值，非真实 TikTok Ads 消耗
- 单条广告 put_days 通常=1（近1天投放），"近30天"是筛选范围，非"30天累计 ROI"
- 要真实 ROI 需广告主自己的 TikTok Ads 后台数据
